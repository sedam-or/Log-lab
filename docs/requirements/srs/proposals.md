## Lampiran A. Usulan perubahan yang menunggu keputusan

Seluruh butir berikut dipindahkan dari audit PRD 13 Oktober 2026. Statusnya tetap nonnormatif: jangan gunakan untuk mengubah implementasi atau acceptance sebelum pemilik proyek menerima atau menolaknya dan keputusan dicatat. Jika disetujui, versi produk dan workbook diperbarui sesuai dampaknya.

### Catatan audit dan perubahan yang diusulkan

Audit silang dengan Modul Praktikum Rekayasa Sistem edisi 2026 dan inspeksi implementasi menemukan tujuh rincian yang perlu dikunci agar acceptance berikutnya dapat diulang. Rincian di bawah ini adalah usulan konkret, bukan requirement normatif v1.0.0. Baseline tetap berlaku sampai pemilik menyetujui amendemen; profil Windows 11 belum diuji. Setelah diputuskan, perubahan yang disetujui menjadi PRD 1.0.1 dan diselaraskan ke workbook, task, tes, traceability, serta PDF.

| Area | Usulan isi amendemen yang dapat ditinjau |
| --- | --- |
| Host Windows 11 | Uji transfer ke VMware Workstation pada Windows 11. Untuk mempertahankan konfigurasi Workstation dan riwayat snapshot, paket utama berupa salinan lengkap folder tiap VM dalam keadaan powered off, termasuk `.vmx`, seluruh `.vmdk`/rantai delta, dan metadata snapshot, dengan manifest SHA-256; ikuti [panduan penyalinan VM Workstation](https://knowledge.broadcom.com/external/article/310359/how-to-copy-workstation-virtual-machine.html). Saat memindahkan VM yang sama, pilih `Moved It` dan jangan jalankan VM asal bersamaan; pilihan `Copied It` mengubah UUID dan MAC. OVA boleh disertakan untuk impor yang mudah, tetapi jangan jadikan OVA satu-satunya bukti pemeliharaan snapshot tree; verifikasi daftar snapshot dan boot pada host lab. Lalu pastikan adapter guest host-only, A/B memakai `172.16.202.21/.22`, host membuka SSH `22` dan HTTPS `8443` memakai CA lab, A mengirim ke B, sertifikat diverifikasi tanpa bypass, dan service guest aktif setelah reboot guest. Simpan versi VMware/Windows, konfigurasi adapter, hasil port/health, serta hash; pisahkan hasil dari acceptance host Linux. Uji start VM setelah reboot host hanya bila mekanisme auto-start dikonfigurasi. |
| Label ML | Tetapkan `normal` untuk empat keluarga `ordinary_login`, `typo_then_success`, `many_users_normal`, dan `boundary_mix` dengan paling banyak 8 kegagalan per window 60 detik. Tetapkan `suspicious` untuk `repeated_failure` atau `account_sweep` yang diskenariokan dengan 10-24 kegagalan per window. Sembilan kegagalan, event/window yang tidak lengkap, kontradiksi skenario, dan kasus tanpa basis label menjadi `unknown` serta tidak masuk fitting/metrik berlabel. Label berasal dari konfigurasi skenario sebelum evaluasi; rules dan prediksi model tidak boleh mengubahnya. Audit mandiri 20% tetap bukan pengganti review independen; laporan harus menyebut nama/jenis reviewer atau menandai pengecualian. |
| Split dan metrik ML | Gunakan grup `run_id`; seluruh snapshot/revisi dan replay turunan satu run wajib berada di satu partisi. Strata run ditentukan oleh ada/tidaknya label `suspicious`. Untuk setiap strata, satu `random.Random(42)` yang dipakai berurutan mengacak daftar run; `ceil(20%)` masuk test, `ceil(20%)` berikutnya masuk validation, sisanya train. Urutan sampel di manifest diurutkan menurut `sample_id`; manifest mencatat versi Python, daftar run/sampel, hash dataset, support kelas, dan overlap event/replay. Ganti nama metrik output `pr_auc` menjadi `average_precision`; hitung dengan `average_precision_score` dan tampilkan sebagai Average Precision (AP), bukan luas trapezoid. Group bootstrap mengambil ulang sebanyak jumlah run dari run test dengan pengembalian, 1.000 kali, seed 42; batas bawah/atas percentile memakai indeks `floor(0.025 × (n - 1))` dan `floor(0.975 × (n - 1))` pada daftar nilai terurut. Catat jumlah replikasi terdefinisi. |
| Prioritas quality-state | Evaluasi urut: sebelum `window_end + 10s` hasil `OPEN`; sesudah grace, window kosong `INCOMPLETE`; bila event ada tetapi heartbeat hilang/lebih tua dari 20s, `STALE`; selain itu kegagalan berikutnya menghasilkan `INCOMPLETE` dengan alasan pertama menurut urutan: offset clock di atas 2.000 ms, event held, ACK watermark di bawah committed sequence, sequence hilang, atau `source_time` belum melewati batas grace. Jika tidak ada kondisi gagal, hasil `READY`. State snapshot bersifat immutable; health heartbeat live ditampilkan terpisah. |
| Keamanan operator | Password memakai `hashlib.scrypt` dengan `N=16384`, `r=8`, `p=1`, salt acak 16 byte, dan output 32 byte; perbandingan hash konstan-waktu. Bootstrap operator membaca `LOGLAB_OPERATOR_USERNAME` dan hash dari secret konfigurasi, membuat akun hanya bila belum ada, dan tidak menimpa akun yang sudah tersimpan. Sesi memakai idle timeout 30 menit. Login/logout wajib membawa token form yang cocok dengan cookie CSRF; untuk semua request yang mengubah state, bila header `Origin` tersedia, nilainya harus sama dengan origin HTTPS pada `Host`. Cookie sesi `Secure`, `HttpOnly`, `SameSite=Strict`; cookie CSRF tidak `HttpOnly` agar dapat dikirim ulang oleh form. Hash, token, dan password mentah tidak masuk dokumentasi/evidence. |
| Kontrak event/API | Byte digest adalah SHA-256 atas JSON UTF-8 dari field event selain `event_digest`, diserialisasi dengan key terurut, `ensure_ascii=true`, dan separator `,`/`:` tanpa spasi. Timestamp memakai RFC 3339 UTC berakhiran `Z`; digest hex huruf kecil. Receipt sukses memuat `status`, `source_id`, `event_id`, `event_digest`; status source memakai nama `acknowledged_sequence`. Error JSON memiliki satu field `error`; kode/status stabil: `unauthorized`/401, `unknown_source`/401, `request_too_large`/413, `invalid_event` atau `invalid_source_status`/422, `event_conflict` atau `sequence_conflict`/409, dan `rate_limited`/429. Fixture bersama harus memverifikasi request, byte digest, receipt, dan tiap kelas error. |
| Batas skor ML | Label `suspicious` diberikan jika probabilitas mentah `>= threshold`; selain itu `normal`. Jangan membulatkan skor sebelum perbandingan. Pembulatan tampilan tidak mengubah label. Sertakan uji nilai sedikit di bawah, sama dengan, dan sedikit di atas threshold. |

Pemetaan usulan ke kontrak: profil host ke OP-01/OP-02; label/split/metrik/threshold ke ML-01-ML-04; state ke AA-02; hash/CSRF ke UI-01; digest/receipt/error ke EP-01-EP-04. Sebelum amendemen disahkan, jangan menyatakan butir ini sebagai ketentuan dosen atau acceptance v1.0.0.
